=== IMAGE CAPTIONING PROJECT PLAN ===
Image Caption Generation
Final Project Planning Document
A free, locally running image-captioning system: a pre-trained BLIP application plus a custom CNN + 2-layer GRU model trained from scratch, with BLIP used as an additional validation mechanism. Built with the Google Antigravity IDE.
1. Project Overview
1.1 Problem statement
The project converts visual information into human-readable language. Given an image, the system must understand its contents and express that understanding as a grammatically meaningful sentence. For example, an image of a dog running in a park should produce: "A dog is running in a grassy park."
1.2 What the user will be able to do
Upload an image.
Let the AI analyze the image.
Receive an automatically generated caption.
View the caption in a simple interface (Gradio).

5. Implementation Plan
5.1 Track A: BLIP application
Create a virtual environment and install dependencies.
Write blip_caption.py that loads the BLIP model once and exposes generate_caption(image, num_beams=5).
Write app.py with a Gradio interface: an image upload, a beam-size slider, and a caption textbox.
Run python app.py, open the local URL (usually http://127.0.0.1:7860), and test with several images. The first run downloads the model (about 1 GB), so internet is needed once.
The code maps directly to the pipeline: convert("RGB") and the processor handle image preprocessing, BLIP's vision transformer is the vision model, model.generate(...) with beam search is language generation, and decode produces the caption. Full code is in Appendix A.
5.2 Track B: CNN + 2-layer GRU trained from scratch
Architecture
Image -> ResNet-50 (frozen, pre-trained) -> 2048-d feature
      -> Linear + tanh -> initial hidden state of a 2-layer GRU
      -> GRU generates words: <start> a dog is running <end>
Encoder: pre-trained ResNet-50 with the classifier removed, used only as a feature extractor and not trained. This keeps the project feasible on a student machine.
Decoder (trained by us): word embedding → 2-layer GRU → linear layer over the vocabulary.
Training: teacher forcing with cross-entropy loss. At each step the GRU sees the correct previous word and learns to predict the next one.
Dataset: Flickr8k, split roughly 80/10/10 into train, validation, and test. COCO is better but too large for a mini-project.
Steps
Build the vocabulary: lowercase, strip punctuation, keep words with frequency of at least 5, special tokens <pad>=0, <start>, <end>, <unk>.
Extract and save 2048-d ResNet-50 features for every image to a single file. This is the slow step; free Google Colab is a fallback if there is no GPU.
Implement the GRU decoder (model.py) and training loop (train.py).
Train for about 20 epochs, evaluating validation loss each epoch and saving the best checkpoint. Stop when validation loss stops improving, since GRUs overfit quickly on small data.
Implement greedy decoding, then optionally beam search (width 3 to 5).

7. Evaluation and Validation Plan
BLIP serves as the second validation mechanism for the custom model. All models are run on the same held-out test images.
7.1 Three checks
Reference-based: BLEU-1 to BLEU-4 of the GRU against the 5 human captions, and BLEU of BLIP against the same captions.
Agreement with BLIP: treat BLIP's caption as a pseudo-reference and score the GRU against it.
Reference-free (optional): CLIPScore for each caption, measuring image-text match without human captions.
7.2 Manual evaluation

8. Interpreting the Results
BLIP will almost certainly win. It was pre-trained on millions of image-text pairs while the GRU saw about 6,000 images. This is expected, and the comparison shows how far a small model trained from scratch can get.
BLIP is a proxy, not ground truth. High agreement means two models say similar things, not that either is correct. It can share errors and can write valid captions that differ from ours. This is why human references and manual rating are also used.
Typical GRU failure modes: generic captions ("a man is standing in the street"), repeated words, wrong objects, and wrong counts.
BLEU on small custom sets looks low. Say so in the report and report the numbers honestly. A clear error analysis is a strong result even if scores are lower than BLIP.

A.1 blip_caption.py (Track A)
import torch
from PIL import Image
from transformers import BlipProcessor, BlipForConditionalGeneration
 
MODEL_ID = "Salesforce/blip-image-captioning-base"
device = "cuda" if torch.cuda.is_available() else "cpu"
 
processor = BlipProcessor.from_pretrained(MODEL_ID)
model = BlipForConditionalGeneration.from_pretrained(MODEL_ID).to(device).eval()
 
def generate_caption(image: Image.Image, num_beams: int = 5,
                     max_new_tokens: int = 40) -> str:
    image = image.convert("RGB")                       # preprocessing
    inputs = processor(images=image, return_tensors="pt").to(device)
    with torch.no_grad():
        out = model.generate(**inputs, num_beams=num_beams,
                             max_new_tokens=max_new_tokens)
    return processor.decode(out[0], skip_special_tokens=True).strip()

A.3 model.py (Track B)
import torch, torch.nn as nn
 
class CaptionGRU(nn.Module):
    def __init__(self, vocab_size, feat_dim=2048, embed_dim=256,
                 hidden_dim=512, num_layers=2, dropout=0.5):
        super().__init__()
        self.num_layers, self.hidden_dim = num_layers, hidden_dim
        self.init_h = nn.Linear(feat_dim, hidden_dim * num_layers)
        self.embed = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.gru = nn.GRU(embed_dim, hidden_dim, num_layers=num_layers,
                          batch_first=True, dropout=dropout)
        self.drop = nn.Dropout(dropout)
        self.fc = nn.Linear(hidden_dim, vocab_size)
 
    def init_hidden(self, feats):
        h = torch.tanh(self.init_h(feats))             # (B, L*H)
        return h.view(-1, self.num_layers,
                      self.hidden_dim).transpose(0, 1).contiguous()
 
    def forward(self, feats, caps):
        # caps: (B, T) = [<start>, w1, ..., <end>, <pad>...]
        out, _ = self.gru(self.drop(self.embed(caps[:, :-1])),
                          self.init_hidden(feats))
        return self.fc(self.drop(out))                 # predicts caps[:, 1:]
 
    @torch.no_grad()
    def generate(self, feats, start_idx, end_idx, max_len=20):  # greedy
        h = self.init_hidden(feats)
        tok = torch.full((feats.size(0), 1), start_idx, device=feats.device)
        ids = []
        for _ in range(max_len):
            out, h = self.gru(self.embed(tok), h)
            tok = self.fc(out[:, -1]).argmax(-1, keepdim=True)
            ids.append(tok)
            if (tok == end_idx).all():
                break
        return torch.cat(ids, dim=1)
A.4 Training step (train.py)
criterion = nn.CrossEntropyLoss(ignore_index=0)       # ignore padding

loss = criterion(logits.reshape(-1, logits.size(-1)),
                 caps[:, 1:].reshape(-1))
loss.backward()
nn.utils.clip_grad_norm_(model.parameters(), 5)

from nltk.translate.bleu_score import corpus_bleu, SmoothingFunction
sm = SmoothingFunction().method1
 
def bleu(refs, hyps):   # refs: [[tokens, ...], ...], hyps: [tokens, ...]
    return {f"BLEU-{n}": corpus_bleu(refs, hyps, weights=[1/n] * n,
                                     smoothing_function=sm)
            for n in range(1, 5)}

2. Introduction
2.1 What is a pre-trained model?
A pre-trained model is a neural network that someone else has already trained on a very large dataset. Instead of teaching a model from nothing, which needs huge data, powerful hardware, and days of training, we download the finished model and use it directly. Reusing knowledge learned on one task for another is called transfer learning.
2.2 Why use one for this project?
No training needed: the model already recognizes common objects, scenes, and actions.
Runs on a normal laptop: generating a caption takes only a few seconds, even on a CPU.
Good quality: it was trained on far more image-text data than a student project could collect.
Free: the model and the libraries are open source, so no paid API is needed.
3. About the BLIP Model
BLIP stands for Bootstrapping Language-Image Pre-training. It was introduced by Salesforce Research (Li et al., 2022) as a model that connects pictures and text. It can describe images and also match images with text.
3.1 How BLIP produces a caption
Image encoder: a Vision Transformer splits the image into small patches and turns them into feature vectors that capture what the image contains.
Text decoder: a transformer language model writes the caption one word at a time. At every step it looks back at the image features to decide which word comes next.
Stopping: the decoder continues until it produces an end-of-sentence token or reaches the maximum length.
3.2 How BLIP was trained
During pre-training, BLIP learned to match images with text and to generate text from images. Web images often come with noisy, low-quality captions, so BLIP uses a method called CapFilt: a captioner writes new synthetic captions, and a filter removes captions that do not fit the image. This gives the model cleaner training data.

=== PROJECT RECOMMENDATIONS ===
Project Recommendations
Image Caption Generation: suggestions to strengthen the project
These are the suggestions I would prioritize, roughly in order of importance.
1. Get Track A working first
Finish the BLIP app end to end before touching the GRU. Then you always have a complete, demonstrable project, and Track B becomes an extension that can only make it better. If time runs short, you can still submit a solid project.
2. Avoid data leakage in the split
Split Flickr8k by image, not by caption. Each image has 5 captions, and if captions from the same image land in both training and test sets, your scores will look better than they should. Use the official train/validation/test split files if your download includes them. Also have your agent print the number of images in each split, so you can confirm they don't overlap.
3. Make the evaluation fair
Lowercase and strip punctuation from every caption (yours, BLIP's, and the human ones) in the same way before computing BLEU.
Use the same test images for every model.
Fix random seeds so your results are repeatable.
Add one or two more metrics if time allows, such as METEOR or CIDEr (the standard captioning metric), alongside BLEU. Several metrics tell a more convincing story than one.
4. State the BLIP comparison honestly
BLIP was pre-trained on far more data than your model, and its captioning version was fine-tuned on COCO-style captions. Your report should say that BLIP is a strong reference rather than a fair contest, and that overlap between its training data and your test images can't be fully ruled out. Examiners generally respect this kind of honesty more than inflated results.
5. Spend your effort on analysis, not just numbers
The most valuable part of the project is probably the error analysis. Pick 15 to 20 cases and categorize them: wrong object, wrong count, missed action, generic caption, repeated words. Showing where and why your model fails demonstrates real understanding.
6. Pick one upgrade, not all of them
If you have time left, choose one extension rather than several:
Beam search vs greedy decoding is the easiest and a clear improvement.
1-layer vs 2-layer GRU ablation is cheap and justifies your design.
Attention is the most impressive but the hardest, so only attempt it if everything else is finished.
7. Keep the development process disciplined
Use Git (even just local commits) so you can undo agent changes that break something.
